# KGA Toolbox 0.2.0 — Release Notes

**Prepared:** 1 October 2026 · **Previous release:** 0.1.0 · **QGIS:** 3.28 – 4.99 · **Licence:** MIT

0.2.0 is the biggest release since the first one. It adds four new tools — **Add
Open Data & Basemaps**, **Imagery Downloader**, **Add Grid to Layout** (with the
first MGRS support QGIS has ever had) and **Raster Format Converter** — a new
**KGA Mapping** toolbar group, and a security, QGIS 4 (Qt 6) and bug-fix pass
over everything new before release. The plugin goes from 41 to **45 algorithms**.

## New tools

### 1. Add Open Data & Basemaps  (`kga:add_data`, group *KGA Data Management*)

One window for getting reference data into a project.

**Administrative boundaries**
- **geoBoundaries** — global ADM0–ADM5 where published; release series gbOpen / gbHumanitarian / gbAuthoritative; simplified or full-detail geometry.
- **HDX / OCHA COD-AB** — the p-coded humanitarian boundaries. One download carries every level, so switching level afterwards is free.
- **Natural Earth** — 1:10m, 1:50m, 1:110m; ADM0 and ADM1; one country or the whole world.
- **Custom address** — a GeoJSON/ZIP/GPKG/KML file, an **ArcGIS REST** layer (paged through so a capped service still arrives complete) or a **WFS** endpoint.
- Result is a scratch layer carrying the publisher, licence and source address in its metadata; the tool says plainly that it must be exported to keep.

**Basemaps** — eleven XYZ services (OpenStreetMap, Google ×5, Esri ×5) plus a custom XYZ URL; optionally saved into the Browser panel. Added at the bottom of the layer tree.

**Elevation (DEM)**
- **Copernicus GLO-30 / GLO-90 on AWS** — no account. Streamed with HTTP range requests: only the blocks inside your area cross the network.
- **OpenTopography** — 13 datasets (SRTM, NASADEM, ALOS, EU DTM, GEBCO, SRTM15+, GEDI L3 …) with a free API key kept in the **QGIS authentication database**.
- Choose the area as the **map extent**, a **rectangle/polygon drawn on the map**, a **polygon layer's boundary** (clip) or **any layer's extent**. Optional reprojection to the project CRS. Size and request limits are checked before the request is made.

**Land cover**
- **Esri 10 m annual land cover** (Sentinel-2, 2017 onward) and **ESA WorldCover 10 m** (2020, 2021). No account.
- The GeoTIFF arrives **classified**: class codes, the publisher's colour table, category names and a raster attribute table (`lc_code`, `lc_class`, count, RGB) readable by QGIS and ArcGIS. Optional **polygon GeoPackage** with `lc_code` / `lc_class`.

**Housekeeping** — downloads are cached under the QGIS profile (500 MB cap, least-recently-used trimmed); the QGIS proxy is honoured; a layer that is already open in the project can never be overwritten.

### 2. Imagery Downloader  (`kga:imagery_downloader`, group *KGA Data Management*)

Downloads web-map tiles for an area and stitches them into one georeferenced image.

- **Area:** map canvas, a layer's extent, a box drawn on the map, or a polygon layer to clip to (pixels outside are masked).
- **Output:** GeoTIFF, JPEG, PNG, JPEG 2000, or ECW (only where your GDAL can write it); project CRS by default (EPSG:3857 is pixel-exact; other CRSs are reprojected).
- **Before you commit:** tile count, image size, ground resolution, estimated download and file size, free-disk check, and a sample-tile probe that spots blank areas.
- **Runs in the background** (a QGIS task): parallel connections (1–16), retries with back-off, and automatic slow-down when the server throttles.
- **Resume:** tiles land in a sparse work file with a checkpoint, so a stopped, crashed or throttled job continues without re-downloading anything.
- Ships with one source, **Google Satellite**, behind an acknowledgement (see *Things to know*).

### 3. Add Grid to Layout  (`kga:add_grid`, new group *KGA Mapping*)

Puts a coordinate grid on a print-layout map from one window instead of five panels.

- Five presets (thin graticule, exterior ticks, zebra, degree graticule, crosses with inside labels), **automatic interval** from the map's own extent, and **editing of the grids a map already has**. Every change is one undo step in the layout designer.
- **MGRS** — which QGIS has no support for — laid down as linked grids: zone and band, 100 km square letters, principal digits and corner values, with optional 1 km mesh and interior label strips.
- Handles the **Norway and Svalbard** zone exceptions, warns when a map spans more than one UTM zone, and builds labels as plain expressions so a project still renders correctly for someone *without* the plugin.

### 4. Raster Format Converter  (`kga:raster_format_converter`, group *KGA Data Conversion*)

Built for orthophotos large enough that a conversion runs for hours.

- Converts between **GeoTIFF, ECW, JPEG 2000, Erdas IMAGINE, PNG and JPEG**.
- Reads the source in blocks (4096 px by default), writes each to disk and records progress in a checkpoint. **Cancel, crash or lose power, then run again with the same output path** — it carries on from the next unfinished block. The blocks are mosaicked and written once at the end.
- **Disk space is checked three times** — before the merge, before the pyramid and after it. Overviews are built into the output as it is written, or as a sidecar `.ovr` if there is no room.
- **ECW licence is checked up front** (the Hexagon encoder refuses at the final write — hours in — if its key is missing). JPEG/PNG band-count, bit-depth and size limits are checked before the run.

## Changes to existing tools

- **New group "KGA Mapping"** — *DEM Legend Bar* moves into it (algorithm id `dem_legend_bar` is unchanged, so models and scripts keep working).
- **Duplicate Checker** — flags now work on **Shapefile layers**. The helper field is renamed `dup_status` (10 characters; the old 11-character name was truncated by DBF so the symbology pointed at a field that did not exist). A failed edit/commit is now reported instead of ignored.
- **Layer packages** carry picture markers that are embedded in the style (`base64:`) without trying to copy them as files.
- **Toolbar** retries once if the first launch after QGIS starts fails, and always logs the full traceback.
- **Plugin unload** now also closes the new windows (Add Data, Imagery Downloader, Add Grid), so nothing is left on the canvas.
- **Domain & Schema Manager** now shares its busy overlay with the new tools (no behaviour change).
- **About dialog, README and metadata** describe the new tools.

## Pre-release review: what was found and fixed

Before tagging, every new tool was reviewed line by line and then **exercised
against live services and real GDAL/QGIS objects**. Findings were fixed, and each
one has a regression test.

### Bugs

| Severity | Where | Problem | Fix |
|---|---|---|---|
| **High** | Add Data → Custom ArcGIS URL | **Large layers were silently truncated.** ArcGIS reports "more records available" under `properties` for GeoJSON replies; the tool looked only at the top level, so it kept the first page and stopped (verified live: a county layer returned 2,000 of 3,000+ features). | Both locations are read. |
| Medium | Add Data → Custom ArcGIS URL | A server that ignores paging would have been queried 50 times and stacked 50 identical copies. A non-collection reply crashed with an `AttributeError`. | Repeated pages are detected and refused with a plain message; bad replies give a sentence. A layer over the 50-page limit is refused rather than returned partial. |
| Medium | Raster Format Converter | **Cancelling during the final merge raised a raw `RuntimeError`** (GDAL raises, it does not return, when its progress callback aborts) and left a half-written output that looked finished. The one-pass path had the same defect. | Cancel and real failures are told apart; partial output is removed, blocks and checkpoint are kept, messages are plain. A block that cannot be written names itself and saves progress. |
| Medium | Add Data (DEM / land cover) | A path typed into *Save to* **overwrote an existing file with no prompt**. | Asks before replacing; a file open in the project is still refused. |
| Medium | Add Data → land-cover polygons | Any polygonising failure other than the expected one threw away a finished raster and left a half-written GeoPackage. | The raster is always added; the polygon error is reported; the partial file is deleted. |
| Low | Imagery Downloader | One unexpected error in a download worker would abort the whole job without saving a checkpoint. | A bad tile is counted as a failed tile. |
| Low | Imagery Downloader | With *checkpoint off*, a throttled stop deleted the work folder while telling the user "progress is saved". | Progress is kept for throttled stops. |

### Security

Static scan (**bandit: 20 findings → 0**, no `# nosec` anywhere) plus manual review:

- **XML from a remote server** (OpenTopography errors) was parsed with the standard-library XML parser, which is open to entity-expansion attacks → replaced with a bounded pattern match (tested against an entity bomb).
- **SQL built from text** (land-cover class names) → a constant statement over a small lookup table; nothing is ever spliced into SQL.
- **API key** — trimmed and percent-encoded into the request, so a pasted trailing space or `&` can neither break the call nor add parameters. Stored only in the QGIS authentication database.
- **Credentials and tokens in pasted URLs** (`user:pass@…`, `?token=…`) were copied into layer attribution and source metadata, which travel with the project and every export → stripped from everything written down (the request itself still uses the full address).
- **Cache integrity** — JSON/GeoJSON cache files are written atomically, so a crash or full disk can never leave a truncated file that the cache would later trust.
- **Silent `except … pass` / `continue` handlers** (16 sites) now use `contextlib.suppress`; retry jitter uses the system random generator.
- Reviewed and found sound: zip extraction (path-traversal guarded), no `eval`/`exec`/`pickle`/`subprocess`/`shell=True`, no disabled TLS verification, GDAL config options restored after every use, filename validation (no traversal), no secrets or personal paths in the repository.

### Qt 6 / QGIS 4 compatibility

A purpose-built scan resolves every `Class.Member` against the real PyQt5/QGIS
classes and flags enum values reached through the class (the spelling PyQt6
removed). It was validated against deliberate bad examples before being trusted.

- **Result: 0 findings across all 87 modules.**
- Fixed: the Imagery Downloader's clip-polygon mode used `QgsWkbTypes.GeometryType.PolygonGeometry`, which QGIS 4 removed — it would have failed on QGIS 4. It now uses `Qgis.GeometryType.Polygon`.
- Also clean: no `exec_()`, `QRegExp`, `QDesktopWidget`, unscoped `Qt.*`/`QMessageBox.*` members, removed `QButtonGroup`/`QComboBox` signal overloads, or `QVariant`-typed `QgsField` calls.

## Network use and privacy

Only **Add Open Data & Basemaps** and **Imagery Downloader** use the network, and
only when you ask for data. They contact geoBoundaries, HDX, Natural Earth (via
GitHub), OpenStreetMap, Google and Esri tile services, the Copernicus DEM and ESA
WorldCover buckets on Amazon S3, Esri's Living Atlas land-cover service,
OpenTopography, and any address you type. **OpenTopography is the only source that
needs an account**; your free API key is kept in the QGIS authentication database
and sent only to OpenTopography. The only information sent is what a request
needs — a country code, the bounding box of the area, or tile numbers. No project
data is uploaded and nothing runs in the background. (The 0.2.0 `metadata.txt`
disclosure was corrected to say all of this.)

## Things to know

- **QGIS 4 / PyQt 6 has not been run on a real QGIS 4.** The QGIS 4 installs on the development machine are installer stubs with no Python. Compatibility is established by the static scan and by using scoped enums throughout; please test on a real QGIS 4 build when one is available.
- **Google imagery and basemaps.** Google's terms restrict bulk downloading of map tiles and use outside Google's own APIs. The Imagery Downloader shows a notice and asks for acknowledgement, and the docs say the same; whether a given use is permitted is the user's responsibility.
- **ECW writing needs a Hexagon licence** (`ECW_ENCODE_KEY` and `ECW_ENCODE_COMPANY`). Without it ECW is hidden from the Imagery Downloader and refused up front by the converter. JPEG 2000 uses the open-source OpenJPEG driver and needs nothing.
- **Add Open Data runs DEM and land-cover downloads on the GUI thread** behind a cancellable progress dialog; very large areas will hold the window. (The Imagery Downloader runs in the background.) Requests are capped (700 M pixels for DEM, 500 M for land cover, 60 M for polygons).
- **Streamed AWS tiles** (Copernicus, WorldCover) go through GDAL, which is given the QGIS proxy but not QGIS's SSL exceptions. Everything fetched through QGIS honours all of QGIS's network settings.
- **Areas crossing the antimeridian** are not supported for DEM or imagery.
- **MGRS** is UTM-based (80°S–84°N); polar UPS is not drawn. A map spanning several zones is gridded for the centre zone and says so.
- **Natural Earth Cambodia has 24 ADM1 units** (its own generalisation, not the official 25) — use geoBoundaries or HDX when the count must be right.
- **Housekeeping, unchanged from 0.1.0:** 29 harmless unused-import notes (pyflakes) remain in older modules, identical to the released baseline, and several older modules enable `gdal.UseExceptions()` process-wide at load (as do the new imagery and converter modules).

## Upgrading from 0.1.0

- Install over 0.1.0 from the Plugin Manager or *Install from ZIP*. Algorithm ids of existing tools are unchanged; the toolbar gains the new tools and the **KGA Mapping** group.
- The Duplicate Checker adds a `dup_status` field (not `is_dup_temp`). A leftover `is_dup_temp` field from 0.1.0 is not removed automatically.
- Downloaded data is cached in `<QGIS profile>/kga_tools/data_cache`; **Clear cache** in the Add Data window empties it.
- Minimum QGIS is still **3.28**.
